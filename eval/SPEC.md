# 评测标准（SPEC）

本文件是人读的单一标准；机器可读的分数曲线/次数/常量在
`eval/robocon_eval/rules.py`，实现与测试在 `eval/robocon_eval/` 与 `eval/tests/`，
规则原文核对见 `docs/RULES-BASIS.md`。

口径分层（全文表格都标注来源）：

- **官方** = 比赛规则 PDF（`~/BiS.d/tmp/队内赛.pdf`）与官方地形/场地资产；
- **实现约定** = 本仓库把官方语义落成可执行判据时做的选择（操作化/更严），
  **不是官方原文，也没有外部确认**；
- 冲突时：官方 > 本文件 > 代码现状。任何语义修改必须同步 `rules.py` + 本文件 + 测试。

## 1. 范围

| 赛项 | 内容 | 满分 | 来源 |
|---|---|---|---|
| Part 1 足式障碍赛 | 8 个障碍，手动遥控/允许固定动作，3 次整场尝试 | 900 | 官方成功定义（25th V1.0 表 2/表 3） |
| Part 2 越障能力测试 | 6 类障碍 × 官方难度，仅 RL，每类最多 4 次 | 1300 | 官方评分表 + PDF 梅花桩图 |
| 总分 | (Part1 + Part2) × 70% + 答辩 × 30% | — | 比赛规则 |

判分只服务本赛题（纯仿真）；不混用全国赛的单场 210 s / 犯规罚分。本模式不判答辩。

## 2. Part 1 判定与计分

### 2.1 赛制

- 场地：`demo/robots/<robot>/scene_part1.xml`（官方几何，仅补语义命名与可动限高杆）。
- 机型：black（12 DoF 足端）/ blackW（16 DoF 轮端），判据语义相同、支撑点类型不同。
- 3 次整场尝试；恢复不消耗尝试，开始/主动重跑/操作跳过消耗；跳过障碍该障碍 0 分且不触发
  回程奖励。
- 失败在尝试内可重试：离开区域后重新武装，成功为最终态。
- 计时在返回启动区且机器人稳定后停止（线速度 ≤0.15 m/s、倾角 ≤10°、持续 0.5 s）。

### 2.2 八个障碍的成功定义（官方 25th V1.0 表 2）

| 障碍 | 成功定义 | 主要失败 |
|---|---|---|
| 直角绕杆 slalom | 从任一圆形必达区出发，S 形绕过每根竖杆，经拐角必达区到另一侧圆形必达区 | 漏杆/乱序/未过拐角 |
| 砂砾碎木坑 gravel_pit | 从 1 m 短边进入或离开；坑面有接触证据，1/2 以上足端触地失败 | 长边/缺口边进出、2+ 足触地 |
| 高墙 high_wall | 从上方跃过或攀爬通过，支撑点全部越过墙平面 | 侧面绕行、未全部越过 |
| 限高杆 height_bar | 任何姿态从下方穿过，横杆未掉落 | 横杆掉落、未从门洞穿过 |
| T 字台阶 t_stairs | 从一条臂上、经另一条臂下；每级顶面至少有足底接触 | 2+ 足触地、漏级 |
| 斜坡 slope | 两侧斜坡上沿 3 m 长边方向累计行走 ≥1 m | 距离不足、2+ 足触地 |
| 木桥 A/B bridge | 从一侧平台经桥面到另一侧平台 | 掉桥、同侧进出、2+ 触地 |

### 2.3 计分

- 每障碍 100 分；T 台阶：异臂上下 100 / 同臂上下 50 / 单向 50；其余 0/100。
- 8 项全部满分且返回启动区：+100 回程奖励（任何部分分/跳过都不触发）。
- `attempt_score = Σ 障碍分 + return_bonus`（0..900）；最终分 = 非跳过尝试的最高分，
  同分取最快有效时长。

### 2.4 实现约定（本仓库，非官方原文）

- 砂砾坑要求进入和离开都走不同的合法短边（官方为“或”）。
- 木桥要求入口/出口侧相对、桥面接触 ≥3 帧、两侧平台均有接触证据。
- 高墙要求 4 个支撑点投影都在墙 x 跨度内跨越墙平面。
- 限高杆要求从门洞 x 范围穿过；高度暂用 base-z 代理（mjdata 几何判定留作后续）。
- T 台阶同臂上下 = 50；只上/只下 = 50；漏级 = 失败。
- 恢复姿态容差 0.30 m / 0.52 rad 是测量余量。

## 3. Part 2 判定与计分

### 3.1 任务目录与官方规则

20 个官方关卡：高台 4 / 楼梯 4 / 斜坡 4 / 高墙 4 / 沟壑 3 / 梅花桩 1。
场景由 `terrain/` 生成：`demo/scenes/part2/part2_official_levels.json` +
`demo/scenes/part2/generated/part2_off_<key>.xml`。

官方规则要点：

- 每种障碍最多 4 次挑战，只记录能通过的最高难度；不计时。
- 仅允许强化学习策略，不能写固定动作。
- 传感器/真值限制同 Part 1；力矩 hip/thigh ≤25 N·m、calf ≤60 N·m。
- 可以自定义地图，但障碍必须保持官方同类；“上述所有障碍均需要能够反复稳定越过”。
- 梅花桩：PDF 说提供地图的参数有误，须按 PDF 图（6 个 0.2 m 方块、两排交错、无坡道）
  自建地图。

### 3.2 官方评分曲线（`rules.py` 同源）

| 类别 | 档位 → 分数 |
|---|---|
| 高台 high_platform | 10/20/30/40 cm → 10/50/100/200 |
| 楼梯 stairs | 10/15/20/30 cm → 10/50/100/200 |
| 斜坡 slope | 20/30/35/45° → 10/50/100/200 |
| 高墙 high_wall | 10/20/30/40 cm → 0/50/100/200（10 cm 以下不得分；本实现取 10 cm = 0） |
| 沟壑 trench | 10 cm = 0，30 cm = 300（20 cm = 150） |
| 梅花桩 plum | 通过 = 200 |

档位之间线性取分、向下取整（比官方“按比例”略严）；类别分 = 成功过的最高难度对应分；
总分为六类之和（满分 1300）。

### 3.3 终端态（本仓库的可执行操作化）

每关独立场景、出生点 x=0、障碍在 x=1.8 m 外、通道中线 y=0。判分只看支撑点（四轮轮底）
与躯干位姿，不读策略内部或训练 reward。

| 类别 | 成功终端 |
|---|---|
| 高台 | 四轮在台顶（轮底 `top-0.06 … top+0.05`）并 hold（0.2 s + 0.1 s 稳定余量）。**官方“上到上平面即得分”，不要求从远侧下去**。 |
| 楼梯 | 四轮到顶平台（`goal_x_min` 后）且 hold → 下完末级、四轮回到 `descend_end_x+0.10` 之后地面并 hold |
| 斜坡 | 四轮在坡顶（`rise_z` 带）hold → 下坡到 `exit_x_min` 后地面 hold |
| 高墙 | 每轮跨 `wall_x` 时 y 在墙跨度内（±0.7 m，防侧绕）→ 全部越墙、回到墙后地面（`wall_x+0.16` 之后）hold |
| 沟壑 | 跨槽 → 四轮在远侧平台顶 → 下完出口坡、回到 `exit_ramp_end` 后地面（z≤0.08）hold |
| 梅花桩 | 跨桩区（任一时刻轮底不低于 `z_cross_min=0.05`）→ 到出口平台（0.2 m 顶带）→ 从出口平台远边下到正常地面并 hold |

公共失败：跌倒（倾角 >75° 或 base z <0.15 m）、四轮支撑证据缺失（fail-closed）、
轮子落入沟槽、梅花桩落地等。**车道 |y|≤0.7 不是官方失败项，本实现也不再据此判失败**；
它只在部分证据检查中用于确认机器人确实在障碍上，防止绕行。

### 3.4 梅花桩几何（按规则 PDF 图重建）

- 入口/出口平台：0.8×0.8×0.2 m，入口 x∈[1.8,2.6]，出口 x∈[4.5,5.3]；
- 6 个 0.2 m 方块，两排交错：第一排 (x,y)=(2.8,0.2)、(3.4,0.2)、(4.0,0.2)；
  第二排 (3.1,-0.2)、(3.7,-0.2)、(4.3,-0.2)；
- 同排方块边距 0.4 m，两排边距 0.2 m；首个方块距平台 0.1 m（第一排）/0.4 m（第二排）；
- 整体外沿长度 3.5 m，中心对称；无坡道，从出口平台远边下 0.2 m 台阶到地面。

几何单一来源：`terrain/gen_plum.py`（生成 `terrain/plum/plum_spec.json`、
`terrain/official/part2_terrain_spec.json` 的 plum 段、判决 manifest 和训练地形）。

### 3.5 全场连续跑不是计分单元

官方 Part 2 按单个障碍计分，不要求一次启动连续跑完全部障碍。本仓库的全场路线只作集成演示：
路线自己的 `PASS` 门限是**集成门限**，不是第二条判据。需要复核全场轨迹时，用手写的投影工具把
每段场地轨迹映射回对应单关坐标，再喂同一个 `Part2OfficialJudge`：

```bash
pixi run -e eval python tools/route/replay_field_part2.py --tag real_v22 --out /tmp/eval.json
```

输出逐段 `success/fail/bypass` 与合计分；`--require-all` 可让任何穿越段非 success 时返回非零。
全场投影是复核/诊断，正式分数仍以单关 eval 运行为准（场地实例的朝向/助跑与单关不完全相同）。

### 3.6 计分与采样

| 项 | 值 |
|---|---|
| 每关尝试 | 4（官方；本仓库内部测试可跑更多，只取成功过的最高难度报分） |
| 判分采样 | 2 ms/帧（judged trace）；旧 20 ms 录制仍可 replay（judge 按 `t` 推进 hold） |
| 不计时 | 每关 `seconds=120` 只是安全帽，不是计分上限 |
| 物理/控制/策略 | 2 ms / 5 ms / 20 ms |
| 确定性 | 固定环境 pin；同输入必须同判定 |

## 4. 人工合规核查（非自动判分）

以下无法从 trace 自动证明，发布成绩前人工核查并记录：

1. **传感器/真值**：输入仅 IMU、关节编码器、相机/雷达；无 body_lin_vel、heightmap、
   foot force/height、body height、特权地形扫描；世界真值只用于生成指令。
2. **Part 2 仅 RL**：无固定动作脚本参与正式跑分。
3. **力矩**：hip/thigh ≤25 N·m，calf ≤60 N·m（训练/部署/评测一致）。
4. **Part 1 遥控/自动**：手动与固定动作同分，无额外加分。
5. **场景/权重哈希**：policy.pt、config.yaml、scene XML、manifest sha256 记录在 trace/产物 meta。

## 5. 已知缺口 / 路线图

- **“反复稳定越过”**：官方备注要求；当前计分只记单次成功，后续用独立随机化重复试验作为
  提交门槛（不混入分数）。
- **mjdata 级裁判接口**：未来 judge 直接读 `mJData`（接触对/几何位姿/支撑点），用于
  “任何瞬间”接触与限高杆几何净空；当前 trace 输入与逻辑不变。
- **Part 1 限高杆 / 高墙**：仍用 base-z 代理；mjdata 几何净空是计划项。
- **Part 2 trace 倾角**：部署 `/eval_state` 不含 tilt/quat 时 replay 退化为 base-z 跌倒检测。
